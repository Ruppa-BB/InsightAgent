# InsightAgent 产品需求文档

> 文档修订 v1.1 · 2026-10-01。需求来源为用户提供的《智能数据分析 Agent 平台 PRD v1.0》；实现建议与产品要求分别标注。本文描述目标设计，不代表功能已实现。

## 1. 定位与目标

本项目当前定位为**个人自学型 MVP**，用于学习数据建模、指标语义层、NL2SQL、受控 Agent、归因分析和可视化。它不是企业可上线版本，也不要求一次覆盖原始 PRD 的全部平台能力。后续再逐步扩展权限、数据接入、RAG、报告和工程化能力。

面向制造业/半导体企业管理者、数据分析师及系统管理员的智能数据分析 Agent 平台。MVP 聚焦销售经营、客户、产品三个主题，产品形态为 **BI Dashboard + AI Copilot + Analysis Workspace**，实现发现问题、分析原因、输出报告的闭环。

学习 MVP 核心 Demo：**“为什么 2011 年 2 月销售额比 1 月下降？”**。销售额、时间范围、比较基线、客户/产品/区域贡献均必须有数据证据，不能仅生成自然语言解释。此处归因指经营数据贡献拆解，不宣称已证明业务因果。

## 2. 学习 MVP 用户与权限

| 角色 | MVP 能力 |
|---|---|
| developer | 单用户使用本地系统，拥有开发和调试权限 |

学习 MVP 只实现本地单用户和最小只读 SQL 安全校验。企业角色、表级授权、字段黑名单和多租户权限放到后续阶段。

## 3. 主用户流程

1. 启动本地 PostgreSQL 和后端，加载生成的销售数据。
2. 在一个分析页面输入“为什么 2011 年 2 月销售额比 1 月下降？”。
3. Agent 解析指标和期间，执行销售趋势、客户、产品、区域贡献查询。
4. 展示 SQL、结果表、至少两种图表、分析步骤和结论。
5. 支持一次上下文追问，例如“再看华东地区”。
6. 保存一次分析 JSON/Markdown 结果，便于复盘。

## 4. 学习 MVP 功能清单与验收

| 模块 | 范围 | 最小验收 |
|---|---|---|
| 数据底座 | PostgreSQL 六表/确认日期、生成数据、核心 SQL | 能按月汇总并按客户/产品/区域对账 |
| 语义层 | 5～8 个指标：销售额、销量、订单数、客户数、毛利额、毛利率、同比、环比 | 指标公式和口径统一，结果可手工复算 |
| Agent 主链 | 受控流程 + SQL/Metric/Metadata/Visualization 四个 Tool | 主问题真实执行，不使用硬编码答案 |
| 归因分析 | 销售下降、客户贡献、产品贡献、区域贡献 | 贡献总额对账，不跨维度重复相加 |
| 分析工作台 | 问题、步骤、SQL、结果、图表、结论、简单 Trace | 可以看懂 Agent 每一步 |
| 会话追问 | 保存当前指标、期间和过滤条件 | “再看华东”能继承上下文 |
| 结果保存 | JSON/Markdown 保存一份分析版本 | 旧结果可打开，包含 SQL 和数据版本 |
| 安全边界 | 只读 SQL、超时、返回行数限制 | DDL/DML/多语句被拒绝 |

## 5. 数据与指标

3 年、30–50 万销售明细、8–12 万订单、500–1000 客户、200–500 产品、10–20 区域。建议默认样本为 800 客户、300 产品、15 区域，属于范围内实现配置，可由生成器调整。

构造方式为公开数据分布参考 + 半导体主数据 + 人工异常注入 + 少量脏数据。Ground Truth 包含八类：销售下降、大客户采购下降、产品结构恶化、新客增长但收入质量下降、客户集中度过高、毛利率下降、客户 × 产品异常、季节性波动。具体幅度由生成配置和验证结果确定。

核心表及口径以 [DATA_MODEL.md](DATA_MODEL.md) 为唯一模型说明。MVP 实现 DWD、DWS、Semantic Layer；完整 ODS → DWD → DWS → ADS 为后续方向。

## 6. 安全与运行边界

本地运行；统一 LLMProvider 支持两个云模型，预留 Ollama/vLLM 接口。SQL 只读，限制表/字段、超时与返回行数。SQL/Python 自动纠错最多 2 次；本设计采用单次运行累计计数；超过即停止并说明失败。Python 不提供用户可编辑执行入口。会话只保存当前任务范围的上下文。

查询超时、最大行数、Step 上限等必须配置并测试，原 PRD 建议为 8–10 Step，不是已锁定常量。无已确认的延迟 SLA、并发指标或准确率百分比，不自行承诺。

## 7. 学习 MVP 成功标准

主 Demo 从加载数据、提出问题、自动归因、查看 SQL/图表到保存分析完整可运行。结果命中生成数据的 Ground Truth，金额及贡献可复算。先准备 8～10 个学习问题即可，不要求完整评估集、PDF、RAG 或双模型切换。

原 PRD 的完整平台范围保留为后续路线。当前学习 MVP 以 2 周、14 个工作日、单人每天约 3～5 小时为目标；延期内容见 [DECISIONS.md](DECISIONS.md)，执行顺序见 [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md)。

## 8. 页面与完整范围验收

导航建议及各页面最小操作见 [需求追踪表](REQUIREMENTS_TRACEABILITY.md)。客户/产品分析、异常中心、数据源、数据质量、指标、知识库、报告、用户管理等必须有可操作入口，可以复用页面组件或采用标签页，不能仅有 API。通知中心是原 PRD 的建议导航项；本版建议先由异常中心承担产品内提醒，独立通知中心不作为验收门槛。

当前学习 MVP 只以本节主链和第 4 节缩减后的功能表作为验收门禁。原 PRD 第 4～40 节的完整能力属于后续路线，未来扩展时再按 [需求追踪表](REQUIREMENTS_TRACEABILITY.md) 验收。

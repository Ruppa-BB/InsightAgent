# D20 启动、演示与交付手册

D1～D20数据管理扩展已完成本次学习版范围；最终制造业PRD仍未完成。当前使用Online Retail II零售数据，货币为GBP，没有真实成本/毛利数据。

## 启动与复现

需要Python 3.13+、uv、PostgreSQL及已导入的Online Retail II基线。

```sh
uv sync --locked
# 首次使用：参考 .env.example 创建 .env 并填写数据库连接。
# 已有 .env 不覆盖，也不要提交到Git。
LLM_PROVIDER=demo uv run uvicorn backend.app.main:app --host 127.0.0.1 --port 8010
```

打开 `http://127.0.0.1:8010/`。`LLM_PROVIDER=demo`覆盖本次进程的模型设置，支持有限示例问题、查询真实数据库，不产生模型费用。需要真实模型时使用已有私密配置启动，不在文档或Git中保存密钥。

检查 `/health` 与 `/health/db`。数据库URL使用SQLAlchemy的 `postgresql+psycopg://` 格式。普通查询账号需要只读权限；隔离导入另需当前应用数据库账号具备创建schema、表和写入该schema权限。应用查询仍设置只读事务；当前尚未实现独立导入账号配置。

全新数据库的基线导入和SQL说明见README、`database/schema.sql`与`database/import_online_retail.sql`。原始Excel、清洗CSV、SQLite历史和截图不在Git中；克隆仓库不能直接获得本机数据、凭证或历史记录。请自行准备公开数据集，不能对已有基线反复直接执行首次建表脚本。

## 10分钟演示顺序

1. `/data`：查看五张注册业务表、字段字典、表关联；演示说明修订，刷新扫描不会覆盖人工说明。
2. `/data/imports`：查看实际完整批次的文件SHA256、清洗统计、事件和发布状态。取消行数包含在无效行数中，不重复相加。不要重复导入完整百万行文件来演示。
3. `/data/quality`：选择已发布数据版本运行检查，再重开保存快照。阈值控制关注标记，不放宽八项硬规则。
4. `/data/metrics`：查看销售额实际发布口径、GBP单位与历史版本。说明编辑不是任意SQL公式编辑；停用会阻止新分析，不重写旧报告。
5. `/`：选择相同数据版本，提问“为什么2011年2月销售额比1月下降？”；查看数字、贡献核对、图表及执行记录，再保存或生成月报。
6. `/data/lineage`：从保存的分析或月报追溯文件、批次、数据版本、表、口径；缺少登记显示未知，不补造历史。
7. `/data/issues`：查看问题处理。现有业务检查没有违规时列表为空是正确结果。失败复检及修复闭环使用隔离测试证据，不修改真实基线制造问题。

实际全量批次清洗805620行、36975订单，总销售额17743429.16 GBP。部分月份只有部分日期，不能把整月覆盖当作已证明。旧分析和报告应按自身保存的数据版本与口径解释。

## 自动验收命令

```sh
uv run pytest -q
INSIGHT_DB_TESTS=1 uv run pytest -q
# 只跑跨模块和问题闭环真实数据库验收：
INSIGHT_DB_TESTS=1 uv run pytest -q tests/test_database_integration.py::test_data_management_end_to_end_evidence tests/test_database_integration.py::test_quality_issue_real_version_recheck
```

默认跳过需要本机数据库的测试；完整验收结果为163项通过，包括20项真实数据库测试。数据库测试采用临时SQLite，导入测试仅修改自身创建的隔离schema并清理。数据库不可用、无建表权限或凭证缺失时，不能把默认跳过结果当作真实数据库验收通过。现有Starlette测试客户端弃用提示仍待后续依赖维护。

## 数据管理知识回顾

| 模块 | 原理 | 学习时要能解释的区别 |
|---|---|---|
| 资产目录 | 从数据库读取结构，人工说明独立修订 | 字段类型不是业务含义，扫描不等于自动理解 |
| 质量管理 | 固定规则、只读快照、不可变检查记录 | 关注阈值与硬门禁不同，样例不等于全部违规 |
| 导入批次 | 源文件指纹、独立schema、事务与发布登记 | 文件一致不代表数据库以后不会改动；两库提交不是分布式事务 |
| 指标口径 | 固定公式模板、草稿、不可变发布与引用 | 编辑说明不等于改变SQL，旧报告必须绑定旧版本 |
| 血缘 | 版本化节点/边与明确证据来源 | 声明依赖不是自动SQL解析，未知来源不能猜测 |
| 问题处理 | 一次消费检查、合并未关闭问题、追加事件、修订号与复检令牌 | 接受风险不等于修复；原版本复检通过后才能关闭 |

## 交付边界

已交付：六个数据管理模块、与受控Agent/月报的版本和质量联动、隔离导入与故障保护、浏览器阶段验收及完整回归。详见D1～D19各阶段文档。

未交付：失败预发布批次直接建问题单、跨版本替代关闭、自动修复、身份与审批、任意数据库/Excel映射、字段级自动血缘、多人协作与生产部署。最终PRD的制造业成本/毛利、动态规划、RAG与真正自学习等仍在后续范围。现有反馈保存不会训练模型。

阶段完成不等于商业软件或最终平台完成。后续优先根据实习需要选择一个真实数据管理场景，再确定新增范围。

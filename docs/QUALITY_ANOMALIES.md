# N4/N5：质量覆盖与销售变化检测

2026-10-03，已实现当前质量检查、历史清洗汇总、月度覆盖、环比下降和移动平均偏离。当前是本地零售样本的规则/基线提醒，尚无季节性调整、ML检测或制造业八类异常真值；这些继续按ROADMAP推进。

## 页面使用

顶部点击“质量与异常”，选择起止月份（均为每月1日，结束不包含），设置环比下降阈值、移动平均偏离阈值和窗口，点击“检查与检测”。默认20%、20%、3个月，均为实现默认配置，不是企业正式规则。

页面展示历史清洗数量、当前质量规则、月度边界/空月、检测基线与状态。JSON下载包含完整基线月份、工具SQL/参数、质量检查与数据版本。报告写入独立SQLite快照，下载同一报告时不重新查询，数值与页面对应。当前未提供报告列表和定时运行，后续看板可复用这些接口。

## N4：质量与历史分开

当前数据库检查8项：明细必要字段为空、数量/单价/金额无效（含非有限数值）、有效订单确认日期缺失、确认早于订单或晚于检查日、重复订单行、重复订单编号、关联/订单上下文不一致、维度编码为空。

检查当前存储的数据；PostgreSQL类型及键约束不能证明原始文件没有类型错误或重复。类型状态明确为数据库已类型化，不给原始文件类型错误编造数量。所有这些规则失败都采用保守的全局阻断：分析返回409 data_quality_failed，检测返回blocked，不生成可信异常判断。原始只读查询工具仍可用于核查数据。

原清洗报告位于data/generated/online_retail_ii/import_report.json。原始1067371行，保留805620行，排除261751行，其中取消19494行。取消数已经包含在排除数中，不能相加。历史报告通过结构检查，并与当前明细数、订单数、金额汇总比较；仅叫“汇总匹配”，不声称逐行原始数据一致。报告缺失、损坏或不匹配分别提示，不自动替换原文件。

月份报告区分：

- within_bounds：整个日历月在当前最早/最晚记录边界内。
- partial_or_outside：部分覆盖或超出边界。
- has_records/empty：该月是否有匹配记录。
- observation_days：实际有交易记录的日期数。
- missing_rate：始终null；没有交易不等于缺失，没有预期记录全集就无法计算缺失率。

2009年12月最早记录为12月1日，属于边界内完整月份；2011年12月最晚记录为12月9日，不能进入完整月检测。边界内完整不证明逐日完整。eligible_for_detection仅描述月份覆盖/记录条件，还要通过全局质量门禁。

每次新的Agent分析都记录质量规则和统计版本，提示缺失率未知；旧分析快照保持旧证据，不会自动追溯更新。环比工具也已与同比共用月份覆盖判断，部分月份返回null；纯环比计算函数仍允许无coverage的旧调用，但生产查询传入覆盖范围。

## N5：检测算法

环比下降：

```text
变化比例 = (当前月销售额 − 上月销售额) / 上月销售额
触发条件：变化比例 < −下降阈值
```

移动平均偏离：

```text
基线 = 当前月份之前连续N个完整月份销售额的算术平均
变化比例 = (当前月销售额 − 基线) / 基线
触发条件：abs(变化比例) > 偏离阈值
```

严格超过阈值才触发，等于20%时不触发。移动平均可提醒增长或下降；环比规则仅提醒下降。窗口2～12个月，默认3。查询历史与当前期分开，避免5年查询上限因补历史而被绕过。

状态为triggered/normal/unavailable/blocked；原因包括质量失败、当前覆盖不足、当前缺月、基期覆盖不足、历史不足、基期缺月、零基数。绝不跳过缺月借用更早的记录，不用未来月份；月总量没有按天数归一化，也没有消除季节性，因此阈值提醒不是业务因果判断。

结果保留当前值、基线值、明确基线月份、比例、阈值、操作符、窗口、检查时间、数据版本及event_id。相同数据、相同请求重复检测得到相同版本/event_id；不同查询范围/过滤/参数可产生不同ID，目前不把它当跨范围全局事件编号。数据版本是统计与月度值指纹，不是全量逐行哈希。

## API

- POST /api/data-quality：DateRange，独立当前质量/月度覆盖报告。
- POST /api/anomalies：AnomalyRequest，独立检测结果，可用现有国家/客户/商品筛选。
- POST /api/monitor：同一只读快照中完成质量与检测并保存报告；页面使用此接口。
- GET /api/monitor/{report_id}/export：下载当次JSON快照，未知报告404。

```json
{
  "start_date": "2011-02-01",
  "end_date": "2011-03-01",
  "mom_drop_threshold": 0.2,
  "moving_average_threshold": 0.2,
  "moving_average_window": 3,
  "filters": {}
}
```

质量报告始终检查全局数据库，过滤只作用于异常金额；页面首版不提供国家/客户筛选控件，可由API使用。所有查询只读，不调用LLM，反馈不会改变阈值。

# N9 月度经营报告

## 行为

页面「经营报告」支持按完整月份生成、查看最近30份报告、重开旧版本，以及下载Markdown和JSON快照。报告包含摘要、指标、销售、客户、产品、异常、发现、风险八部分，另附查询证据。模板确定性生成，无模型调用。

报告为全量零售月报，单位GBP、有效订单completed；选择月份后重新读取报告专属快照，不复用先前分析的筛选或把多次分析拼接成同一快照。从分析页打开时预填分析起始月份，仍需按完整月份生成。没有成本、毛利和税额事实，明确写入风险。

## 数据一致性与版本

- 每份报告独立run ID与report ID：同一只读REPEATABLE READ连接内查询六项指标、趋势、Top客户/商品、变化提醒，以及客户/商品/国家贡献。贡献各自与销售额差额对账，不能跨维度相加。
- 异常部分只展示报告月份，并保留方法、阈值、基线月份、基线金额、触发状态与不可计算原因。
- 当前月份覆盖不足时拒绝生成；基期不完整或无匹配记录时生成带限制的报告，不执行强比较/贡献。零基数比例不可计算。
- 快照包括SQL、绑定参数、质量规则与统计版本、检测结果和贡献汇总。序列化后用规范JSON计算SHA-256。它校验保存的报告快照内容，不是整个数据库逐行版本。
- Markdown和JSON一次保存。重开/导出只读SQLite，不查询PostgreSQL，不重跑模板。重复生成同月创建新ID，旧报告不覆盖。没有编辑/删除/自动定时生成。
- 沿用N8步骤/时间预算与失败run记录；dashboard_snapshot是组合工具，内部SQL数量不等于步骤数。存储失败或预算失败不展示成功报告。
- 页面只渲染正文，下载Markdown附完整查询证据；安全预览通过textContent构造标题、段落与表格，不执行报告中的HTML。维度名称在Markdown中转义。

## API

| API | 行为 |
|---|---|
| POST /api/reports | body `{"month":"2011-02-01"}`，生成新报告 |
| GET /api/reports | 最近30份元数据 |
| GET /api/reports/{id} | 保存的报告与快照 |
| GET /api/reports/{id}/export/md | 固定Markdown附件 |
| GET /api/reports/{id}/export/json | 固定JSON附件 |

未知ID404，非法月份/格式422，质量或贡献校验失败不保存业务结论。PDF属于后续原PRD里程碑，本阶段只交付Markdown/JSON。

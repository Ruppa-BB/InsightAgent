## 文件

- `tests/evaluation/questions.json`：28题、分类、上下文、标准意图与固定检查项。
- `scripts/evaluate_agent.py`：评测器及独立参考SQL；不导入生产SQL白名单或查询构造器作为答案。
- `n1-offline-baseline.json`：全量离线基线，逐题预期/实际、参考SQL/参数/结果、警告、数据指纹。
- `n1-live-sample.json`：真实模型小样本，实际计划、逐题用量和标准执行核对。
- `tests/test_evaluation.py`：评测器自身的错误检测、分母、禁止离线模型调用、执行隔离及预算保护测试。

参考SQL与产品代码都对同一业务定义建模，并非人工业务审计。参考聚合仅关联订单与明细，过滤用EXISTS、维度通过独立查询取值，以降低与生产完整多表JOIN共享错误的风险。January/February及英国金额、订单数、客户数另有固定锚点；结果偏离会失败，不能用当下数据库结果自动覆盖锚点。

## 运行

在项目根目录，先确保原数据和`.env`仍存在：

```sh
# 不调用任何模型，真实读取本机PostgreSQL
uv run python -m scripts.evaluate_agent

# 单题离线调试
uv run python -m scripts.evaluate_agent --cases Q07

# 付费联调：显式选择最多5题，默认配置仍保持低成本
uv run python -m scripts.evaluate_agent --mode live --cases Q13 Q20 Q27 \
  --output data/artifacts/evaluation-live.json

# 测试评测器，不需调用模型或连接数据库
uv run python -m pytest -q tests/test_evaluation.py
```

默认报告位于Git忽略的`data/artifacts/evaluation-offline.json`。实时运行结果只有经过核对后才复制为新的基线；保留旧基线，不要悄悄覆盖失败项。

退出码：0全部适用项通过且数据汇总未变化；1存在失败/错误或数据汇总变化；2配置/题号/运行初始化错误。**当前完整离线运行返回1是预期现象**，因为5个规则能力缺口仍然存在。

## 评测契约与保护

- 解析检查status及规范化后的全部意图字段：action、metric、期间、基期、维度、筛选。日期和筛选不允许漏掉；澄清必须无可执行意图且有问题文本，不要求逐字匹配澄清文案。
- 执行检查实际金额、去重计数、日期分组、基期与差额、零分母、空数据、数据覆盖提示、截断，以及销售贡献分别对账。同比/毛利/真正TopN等未来能力不冒充已支持，后续新增题集版本。
- 查询参考SQL全量分组后核对前500组及截断状态；截断结果不当完整贡献。
- 离线解析直接使用parse_demo，绝不经过已配置的真实provider；执行输入来自人工标准意图，模型解析和执行成绩分开。
- 真实解析失败时不执行模型提出的计划；标准意图执行只是在独立验证工具。当前未另报端到端模型执行准确率。
- 所有评测执行历史写入临时SQLite，结束后清理，用户原分析历史不变。数据库使用只读事务。
- 报告无API Key、数据库URL或底层驱动错误；模型服务错误只记公开错误代码。失败调用可能已产生费用而没有返回usage，目前报告仅统计收到的用量，不把未知费用视为零。
- 指纹含明细数、订单数、日期范围、销售额；它是汇总指纹，不是全量内容哈希。运行期间应保持本机样本不变；汇总未变化也不能证明每行未变化。参考与产品各自在只读快照内运行，跨运行一致性依赖固定样本。

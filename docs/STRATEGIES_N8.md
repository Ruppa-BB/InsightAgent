# N8 受控策略、累计预算与运行记录

## 已实现

三种策略只选择固定工具，模型提供策略名和类型化参数，不提供SQL/Python代码：

| 策略 | 允许输入 | 行为 |
|---|---|---|
| sales_decline 销售变化/下降分析 | 销售额两期比较 | 查询两期总额，按所选维度完整贡献对账；实际增长也如实展示，不预设下降 |
| customer_contribution 客户贡献 | 销售额两期比较 | 查询两期总额，只执行客户贡献 |
| product_mix 产品结构 | 销售额趋势或比较 | 趋势时查询全部商品金额与销售额占比并对账；比较时执行商品变化贡献 |

`AnalysisIntent.strategy` 默认为auto，兼容旧记录。auto下销售额compare执行销售变化，销售额按商品trend执行产品结构，其他合法请求仍走基础查询。显式不兼容策略拒绝。页面「分析策略」下拉或模型结构化意图可选择策略；切换其他指标时页面重置auto，下钻接口未显式指定策略时也重置不兼容策略。组合按钮回到auto，保留N7组合能力。

产品结构最多10000商品组，全量聚合后对账；图表只展示前20，数据/导出保留完整结果。销售额占比不是销量占比、毛利占比或业务因果。去重订单数与平均值不能用此策略做可加贡献。

## 预算与运行生命周期

每次 `/api/analyze`、结构化分析或下钻创建一个新运行ID；同次运行共享一个预算对象，解析到执行不重置预算。累计步骤含问题解析（自然语言请求）、质量工具、元数据工具、指标/同比/贡献/商品结构工具和最终差额校验。组合工具内部可运行多个固定SQL，步骤数不是SQL语句数。SQLite运行记录写入不算业务工具步骤。

默认配置：

- `AGENT_MAX_STEPS=12`：启动新工具前检查，预算耗尽不启动后续工具。
- `AGENT_MAX_DURATION_MS=60000`：工具前后检查累计耗时；不是进程强制中断。正在执行的SQL仍受现有5秒statement_timeout，模型请求仍受已有30秒网络超时。
- `AGENT_MAX_MODEL_CALLS=1`：实际模型HTTP请求前预占调用额度，失败请求也计入。缓存和本地精确追问不占模型额度。
- `AGENT_MAX_TOKENS=4096`：响应收到后累计服务商返回的total_tokens；超过预算停止数据库分析。不能提前精确计算服务商输入tokens，已经发生的模型请求费用不会撤销。原700输出token上限继续限制单次响应。

当前策略无重试：工具/模型失败即停止，重试次数0，失败不会重置预算或改用昂贵模型。未响应时token用量标为未知，不把失败请求当免费。未来若增加恢复，必须沿用同一预算对象，而不是新建运行。

运行步骤保留序号、工具名、状态、耗时和安全错误码；总记录保留策略、累计用量、限制、状态和关联分析ID。成功分析JSON/Markdown包含运行快照，历史加载回显；失败不保存业务结论，但保存运行失败记录。API错误返回run_id，`GET /api/runs/{run_id}`可核验；页面错误时展开运行面板。

运行持久化是SQLite新增表，不覆盖旧分析与反馈。存储本身不可写或进程被强制终止时，不能保证最终状态落盘；异常恢复、队列和中断任务回收尚未实现。

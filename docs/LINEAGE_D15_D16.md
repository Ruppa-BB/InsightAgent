# D15～D16：数据血缘与影响追踪

2026-10-06完成。入口 `/data/lineage`。本轮完成既有零售MVP的表级血缘，下一阶段D17～D18是质量问题处理与复检闭环。最终目标仍遵循原PRD，制造业M2继续暂缓。

## 能用它做什么

从分析或月报的「追溯数据来源」进入，查看当时使用的数据版本、指标口径版本和文件/批次来源。选择数据表并切换「下游」，查看可能受到该表影响的指标版本绑定，以及有证据的已保存分析/报告。资产目录、导入批次和指标历史也提供直接入口。

节点可点击继续追踪；页面按阶段排列，关系表明确实际连线。分层视图的同列可能有并行分支，不能把相邻卡片直接当成一条实际处理流水线。源文件节点显示SHA-256，批次节点显示当前状态和清洗程序版本登记情况；基线表跳转原public资产，隔离表跳转对应批次，不冒充资产目录已扫描过隔离schema。

## 数据管理原理

血缘是有方向的图。节点表示资产或记录，边表示有依据的关联。它回答「来源是什么」和「哪些结果可能受影响」，不证明数据值正确，也不证明经营原因。

| 节点 | 稳定标识与来源 |
|---|---|
| 源文件 | source:SHA256，来自导入副本指纹登记 |
| 批次 | batch:批次ID，来自导入记录 |
| 数据版本 | dataset:version_id，来自发布登记；基线明确为public |
| 表实例 | table:version_id:table，两个版本的同名表不是同一节点 |
| 固定模板 | template:retail-sql-v1:metric_code，人工审核的代码依赖声明 |
| 指标口径 | metric:metric_code:v版本，来自不可变发布记录或保存的口径证据 |
| 版本绑定 | binding:数据版本:指标代码:v口径版本，避免数据版本相互串线 |
| 分析/月报 | analysis:ID / report:ID，来自保存记录，不重跑数据库 |
| 未登记 | 明确缺失的来源、批次、口径或计算依赖，不自动填当前版本 |

关键设计是「版本绑定」。若把两个数据版本的表直接连到同一个全局指标，然后从指标连到所有报告，第一版表的下游就会错误包含第二版报告。现在全局口径只提供定义；实际数据依赖先进入各自的数据＋口径绑定，再连接消费该绑定的保存记录。

## 三类依据与一个边界

- `recorded`：保存的文件→批次、批次→发布版本、版本→分析/报告来源，以及版本绑定→实际分析/报告消费记录。
- `registered`：已登记版本中的表实例、绑定的口径版本。
- `declared`：代码审核的模板定义与表级计算依赖，表示潜在影响。未连接消费记录的绑定不能宣称已产生分析结果。
- `unknown`：缺少登记。原基线没有可信的原始文件/批次登记；早期分析或报告没保存口径版本时，不会自动连到当前v2。

依赖声明版本为`retail-sql-v1`。现有SQL BASE_FROM对六项基础指标统一JOIN五张表，派生同比/环比复用该销售查询，所以五张表均属于声明依赖；不能因为订单数公式只写order_id就漏掉实际JOIN影响。本阶段不做任意SQL解析，也不是字段级或逐行血缘。SQL模板变化时需审核并升级依赖声明，不自动推断新的语义。

旧记录有数据版本但没有口径版本时，可以证明数据来源；无法证明其指标绑定，因此不从某一张表补造实际消费边。数据版本节点的下游仍能找到这些已保存来源记录，报告上游会保留「历史口径未登记」。

## 持久化与一致性

新增SQLite迁移5，`dm_lineage_nodes`存节点，`dm_lineage_edges`以(source,target,relation)唯一去重，并为target建索引。发布批次、发布指标、保存分析及保存月报时，在同一应用数据库事务中同步登记；登记失败不留下仅保存业务记录而缺少血缘的半成品。PostgreSQL与SQLite仍不是分布式事务，导入跨库恢复限制沿用D8～D11。

读取页面也按登记账本幂等补齐历史索引，BEGIN IMMEDIATE保证索引同步与读取一致。它不修改旧分析/月报JSON、Markdown或哈希，不扫描业务PostgreSQL，也不调用模型。批次状态可以刷新，版本和消费关系来自各自保存内容，不随分析页当前选择或当前指标发布指针改变。

这是本机少量历史记录的实现：同步会遍历保存账本，追踪使用带visited集合的图遍历，循环不会无限递归。未来大量记录应改为增量事件、分页与更细粒度索引；目前没有通用图数据库、任意边编辑或生产级多租户权限。外部直接修改/删除登记账本不属于页面正常流程，也不保证索引能自动修复此类破坏。

## API

| 接口 | 行为 |
|---|---|
| GET /api/data/lineage | 登记同步后的节点、边、依赖声明版本 |
| GET /api/data/lineage/trace?node_id=...&direction=upstream | 查看原来源和口径；包含未知证据计数 |
| GET /api/data/lineage/trace?node_id=...&direction=downstream | 查看潜在影响与有证据的实际消费 |

不存在的节点404，非法方向422；节点ID作为值匹配，不执行SQL/文件路径。页面URL保存节点和方向，刷新可重开同一追踪对象。

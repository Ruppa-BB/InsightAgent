## 自动测试

命令：`INSIGHT_DB_TESTS=1 uv run python -m pytest -q`

本次结果：**44 passed**，包括 40 个输入/逻辑/API 测试和 4 个真实 PostgreSQL 集成测试。普通测试默认跳过数据库集成项。

检查范围：

- 日期顺序、闰日、严格 5 日历年、日期上限、非法指标/维度/字段/limit。
- 用户字符串绑定为参数；截断结果明确标记。
- 新增/消失对象均计入贡献；对账不一致拒绝结论；零基数和缺月不编造环比。
- 模型计划格式校验，禁止 SQL 作为模型输出执行；无凭证时显式失败。
- API 查询、保存/读回/导出、会话继承、无效会话、澄清和超时响应。
- PostgreSQL read-only 模式拒绝 DELETE WHERE false（即使保护失败也不会删行）。
- 100ms 配置下 pg_sleep(1) 被取消，事务结束后连接池设置恢复，连接可再次使用。
- 真实数据主问题和 2 月销售额环比。

曾发现短测试 pg_sleep(0.2) 的时间间隔不足，发生一次未取消。检查 SHOW statement_timeout 确认设置为 100ms，并连续验证较长查询被取消后，将验收查询延长为 1 秒。最终整套测试通过；生产默认仍为 5 秒单语句超时。

测试环境有一条 Starlette 对 httpx 测试适配器的弃用提示，不影响通过结果；后续升级测试依赖时再处理。

## 已知边界

- 真实 LLM 尚未联调；仅模型协议适配和格式校验通过模拟响应测试。
- Agent 使用固定、有限的工具编排。没有任意 SQL、任意 Python、多 Agent、自主学习或自由多轮规划。
- demo 仅支持明确列出的有限句式，不支持所有自然语言问法。
- 会话继承最近成功意图，尚未保存多轮澄清状态。没有用户权限、登录或多人会话隔离。
- 分析历史在本地 SQLite，不代表已经实现最终产品的资产版本、企业报告或云部署。
- 金额描述依赖源数据清洗口径。Online Retail II 不提供成本，取消记录已排除，不能将这些销售额直接解释为完整净收入。

## 2. 项目阶段关系

最终目标是用户提供的PRD所定义的智能数据分析Agent平台。第一阶段是个人自学型MVP，用于逐步实现并理解核心数据分析Agent链路。第一阶段已完成只代表阶段一门禁通过，不代表最终产品完成；第二阶段及后续继续实现原PRD暂缓能力。

## 3. 第一阶段学习 MVP 范围

当前只保留：PostgreSQL 本地数据、5～8 个核心指标、单用户、一个 LLM、SQL/Metric/Metadata/Visualization 四个 Tool、销售下降归因、简单图表、会话追问、Trace 和 JSON/Markdown 保存。

暂不实现：完整三角色、四种数据接入、RAG、PDF、Redis、Python 任意执行、双模型、八类异常、完整前端导航、复杂版本快照和企业权限。

## 5. 阶段一设计约定

| ID | 约定 | 理由及限制 |
|---|---|---|
| D01 | 按confirmed_date统计有效确认订单；目标迁移现有schema | 满足确认后不含税金额要求；不宣称财务收入确认 |
| D02 | 模拟数据人民币、不含运费、折后价格、历史成本快照、行舍入 | 控制模拟数据复杂度；外部源须显式映射 |
| D03 | 客单价=S/去重订单数；新客按首笔有效确认订单月份 | 原PRD未给公式，界面须显示定义；改变时版本化 |
| D04 | 比率零分母NULL；同维度净贡献可负；不跨维度累加 | 避免错误归因和错误汇总 |
| D05 | 自动纠错SQL/Python按一次运行累计最多2次 | 原PRD未明确跨工具计数，本版采用更保守有限恢复 |
| D06 | 结果快照保存旧证据，冻结Demo数据支持重放 | 外部可变源不承诺历史重算 |
| D07 | 导入基础质量和异常规则前置；统计方法与展示后续补齐 | 先满足导入和异常入口的依赖 |

## 6. 实现建议与待配置

当前学习 MVP 使用已导入的 Online Retail II 数据、一个模型和单用户本地运行。计划总计14个工作日，Day 1～4 已完成，剩余10个工作日用于指标语义、SQL Tool、模型接入、Agent编排、归因、可视化和演示。Embedding、云模型、异常幅度、Step/Token/超时/行数等按学习过程逐步确定。

Step建议按工具调用计数，重试计入，模型调用和Token另设预算；初始8～10工具调用目标须通过主链验证。所有示例数字均不能写成实际经营结论。公开参考数据记录来源和可用条件，不将未核验分布冒充真实企业数据。

## 7. 后续阶段路线与范围边界

原PRD第42节明确将以下功能放入后续阶段：多租户、多组织、定时同步/报告、企业微信/钉钉通知、Web Search、历史案例记忆、Python编辑执行、拖拽BI、自定义Dashboard、自动推荐问题、自然语言改图、Excel报告导出、CI/CD、ML异常检测、完整指标血缘、跨会话Memory。这些是最终目标内的阶段性延期项，不是从产品范围删除。

原PRD第41节部署顺序为本地→Docker→云服务器→CI/CD；后续部署不作为本地MVP验收门槛。本版建议由异常中心承担提醒，独立通知中心后续评估；这属于导航取舍建议。完整ODS/ADS、复杂慢变维度、退货退款、多币种不纳入当前实现计划。

## 8. 变更与实际状态

取消原PRD明确能力、改变正式指标含义或替换关键技术时记录理由、影响和决策依据；日常可逆实现细节自主处理。变更同步受影响设计及追踪表。

本次只修订文档，未修改schema、初始化数据库或实现API。现有六表SQL缺确认日期、DWS及应用存储。实际交付状态需执行验证后更新，不能按开发计划自动推定完成。

## 2026-10-03 后续规划决策

- 原始PRD仍为最终产品需求基线；新的当前排期见 [ROADMAP.md](ROADMAP.md)，原14日计划保留历史。
- 现有零售分析主链已完成初步验收，真实DeepSeek已联通；这不代表完整平台或自学习完成。
- 原PRD反馈用于评估，案例记忆属于后续增强。优先评测/反馈及看板→异常→分析→报告，案例复用单独做可撤回、可验证的实验。
- 制造业模拟数据与现有零售样本隔离。只有具备明确成本、单位、日期和业务口径的数据才能支持毛利，不把零售数据包装成制造业事实。
- 本轮仅规划；近期10个开发工作日按每天3～5小时估算，所有门禁通过后再宣布阶段完成。

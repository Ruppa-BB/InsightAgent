# D19 数据管理整体验收

本次验收范围是现有 Online Retail II 单用户本地 MVP 的六个数据管理模块及 Agent 联动，不代表最终制造业 PRD 已完成。

## 同源全链路

新增 `test_data_management_end_to_end_evidence`，使用本次创建的隔离 CSV、独立 SQLite 和独立 PostgreSQL schema：

1. 注册、清洗、核验并发布导入批次；相同文件再次登记返回同一批次。
2. 扫描五张注册业务表的资产目录。
3. 选择发布版本，运行并保存八项质量检查，检查绑定该版本。
4. 执行结构化趋势分析，得到单行样本对应的1月2 GBP、2月4 GBP，核对源文件 SHA256。
5. 生成2月月报，追溯同一源文件、批次、数据版本和销售额口径v1，未知来源节点为0。
6. 发布销售额停用v2，新分析被拒绝；旧分析仍引用v1，旧月报内容与哈希、旧血缘图全部保持不变。
7. 结束后清理仅由该测试创建的 schema。

以上不请求模型，验证的是结构化计划之后的完整工具与数据管理链路；自然语言模型解析已由M1既有验收覆盖。

## 问题处理与故障保护

扩展真实质量闭环测试，证明人工豁免后，Agent依然读取实时质量结果并拒绝分析；重新打开后完成失败复检、原版本修复、成功复检与关闭。问题关闭只证明复检时的快照，不代表后续数据不会改变。

现有回归同时覆盖：导入事务失败回滚、未发布版本不可选择、检查失败不建违规问题、迟到或取消复检不能关闭、并发修订冲突、指标停用、保存/发布与血缘登记原子性、未知历史来源不伪造、查询只读与超时。此前D1～D18浏览器证据记录保留在对应阶段文档；D19新增证据为跨模块真实数据库链路。

## 流程边界

当前导入的预发布质量校验不合格时批次不会发布；问题单来自对已可查询版本执行的完成检查。失败批次尚不能直接转成质量问题单；修正文件再导入是新版本，不能替代原版本复检来关闭旧问题。原计划中的“预检问题直接建单再发布”不是当前已交付行为，不能在演示中宣称完成。

当前目录扫描是五张注册业务表的基础目录；导入版本的表身份由数据版本与血缘表示，不声称支持任意数据库资产扫描。口径的可编辑范围是名称、说明和启用状态，公式模板仍固定。

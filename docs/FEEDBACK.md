# N2 分析反馈

2026-10-03：已实现本机单用户反馈，与原PRD第34节对应。反馈用于后续评估；目前不会自动训练模型、检索案例或改变分析逻辑。

## 页面操作

打开一条分析，在图表及查询依据下方选择“有帮助 / 无帮助”，可填写原因与修正建议，然后保存。重新打开分析历史会回显原反馈，可以修改后更新。未保存的输入在刷新页面后不会保留；保存失败时当前表单内容保留并提示重试。

一条分析只有一份当前反馈，按分析ID关联，不按会话共用。完全相同的内容（忽略文本首尾空白）重复提交，保持原时间和revision；内容改变后递增revision，保留首次created_at、更新updated_at。当前保存最新内容和修订次数，不保存逐版反馈正文，不宣称已有完整反馈审计历史。

## API契约

- `GET /api/analyses/{analysis_id}/feedback`：返回`{"feedback": null}`或已保存反馈；分析不存在返回404。
- `PUT /api/analyses/{analysis_id}/feedback`：创建或更新当前反馈。
- 新分析结果有`feedback: null`；历史详情及JSON/Markdown导出附带当前反馈，不改原分析的数字、SQL、意图、结论和上下文。

请求示例：

```json
{
  "rating": "not_helpful",
  "reason": "两个月份天数不同，希望比较日均表现",
  "correction": "保留总额比较，同时补充日均销售额"
}
```

rating必须是helpful或not_helpful。reason选填，最多1000字符；correction选填，最多2000字符；首尾空白清理；未知字段、无效UUID、超长输入拒绝。响应包括analysis_id、rating、reason、correction、created_at、updated_at和revision，时间为UTC。

## 存储与边界

在原本地SQLite中新增analysis_feedback表，analysis_id是主键和analyses外键。开启SQLite外键校验，在写事务中检查分析存在，再比较并写入反馈。首次使用自动增加表，兼容没有反馈字段的旧分析记录，无需重新导入业务数据。

原分析JSON快照不被反馈更新；GET详情/导出动态附加当前反馈，因此同一分析不同时间导出的反馈部分可能变化，而历史分析证据保持原值。会话上下文仍只读取原intent。当前是单用户，不宣称已经实现用户级访问控制。

反馈文本保存在本机，不发送给DeepSeek；前端回显写入textarea.value，不解析成HTML。纠正建议是待核验的用户意见，不能自动当成事实、指标定义或可执行代码，也不会覆盖N1标准答案。

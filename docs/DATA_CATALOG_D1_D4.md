## D1实体模型与后续衔接

| 实体 | 本次实现 / 后续设计 |
|---|---|
| Dataset | dm_datasets：稳定id、当前登记版本、来源说明、单位；本次固定online-retail-ii |
| DatasetVersion | 本次baseline-v1只作现有数据登记；D8～D11扩为独立不可变版本，关联导入批次和固定目标 |
| Asset | dm_assets：dataset_id+table_name稳定id、技术快照JSON、扫描时间；快照内含列、约束和行数 |
| Description | dm_descriptions：asset_id+field_name主键；空字段名代表表说明；独立revision和更新时间 |
| SchemaMigration | dm_schema_versions：当前版本1，增量建表；不删除或改写已有分析历史 |
| ImportBatch | D8～D11：文件指纹、清洗统计、任务状态、版本；禁止同批次重复发布 |
| QualityCheck / Issue | D5～D7及D17～D18：规则版本、检测结果、问题处理与复检证据，按数据集版本关联 |
| MetricVersion | D12～D14：已发布口径版本；历史分析绑定当时定义 |
| LineageEdge | D15～D16：版本化上下游节点、登记来源；未登记关系未知 |

后续实体目前仅设计，尚未创建空功能或假记录。D1～D4沿用现有SQLite存应用元数据，PostgreSQL存经营数据；不迁移历史或修改业务表。主外键技术关系来自数据库，指标关联为明确登记的事实依赖/可分析维度，不等同于完整字段级血缘。dim_date不在本轮五表扫描范围；约束可能引用它。

## 已实现

- 五表技术扫描：列名、类型、空值约束、生成字段、默认值、主键/外键/唯一键、准确行数；同次只读快照读取。
- 全部技术扫描成功后才原子更新目录；失败保留上一次快照。重复扫描稳定ID，不新增重复资产。
- 业务说明与技术快照分开保存；刷新不覆盖人工编辑。expected_revision拒绝旧版本覆盖；相同内容重复保存不增加revision。
- 页面检索表名/字段/业务说明；资产详情展示关系与关联指标。点击指标跳转分析工作台并填入问题，需用户确认后才执行。
- 成本/毛利字段标记不可用；明确默认国家、产品单位、标准售价、分类/行业和获客日期的源数据限制。

默认参考定义与人工说明分别展示。未填写的说明保持未知，不调用模型猜测。未实施用户权限、批次管理、指标发布和自动血缘。

## 学习知识点

技术元数据描述表结构，业务元数据解释字段；二者必须分开维护。稳定ID确保刷新是更新而非重复登记。revision实现乐观并发控制，防止旧页面覆盖新说明。REPEATABLE READ确保扫描同次一致；先读后原子保存保证失败不留下半份目录。存在字段不证明存在可信业务事实，尤其不能用占位成本推算毛利。

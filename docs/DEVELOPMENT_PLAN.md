# InsightAgent 两周学习 MVP 计划

> 版本：v1.2 · 2026-10-02。目标是单人、每天约 3～5 小时，在 14 个工作日内完成一条可运行的销售下降归因链路。每天必须留下可运行的结果；如果当天任务未通过验收，第二天先修复。

## 目标和边界

两周结束时，系统应能完成：

```text
生成销售数据 → 指标查询 → Agent 理解问题 → SQL 执行
→ 客户/产品/区域归因 → 图表 → 结论 → 保存 Markdown
```

本周期只实现单用户、本地 PostgreSQL、一个 LLM、SQL/Metric/Metadata/Visualization 四个 Tool。RAG、PDF、Python 任意执行、Redis、MySQL/Excel 接入、企业权限、完整 Dashboard、双模型和八类异常全部延期。

## 每日任务

| 天数 | 学习目标 | 编码与产出 | 当天验收 | 明确不做 |
|---|---|---|---|---|
| Day 1 | 熟悉数据模型和 PostgreSQL | 执行基础 schema；补 `confirmed_date` 迁移；写月度销售汇总 SQL；记录口径 | 空库可初始化；销售额、毛利、订单数、客户数能查出 | 不做前端和 Agent |
| Day 2 | 学习可复现数据生成 | 实现区域、客户、产品、日期、订单、明细生成器；固定随机种子 | 生成小数据集；外键、金额、毛利和 completed 过滤正确 | 不追求 30～50 万明细 |
| Day 3 | 学习异常构造和对账 | 使用真实的 2011 年 2 月下降场景；实现月度汇总；写对账 SQL | 能查出 2 月比 1 月下降；差异可解释 | 不做八类 Ground Truth |
| Day 4 | 学习 FastAPI 数据服务 | 创建 FastAPI；实现 `/health`、`/overview`、`/sales/trend`、`/sales/breakdown` | API 返回真实数据库数据；不返回硬编码答案 | 不做登录和复杂 RBAC |
| Day 5 | 学习指标语义层 | 建立 5～8 个指标定义；实现 MetricService 和 MetadataService | 指标带公式、单位、过滤和口径；API 可读取 | 不做自然语言创建指标 |
| Day 6 | 学习安全 SQL 执行 | 实现只读校验、单语句限制、危险关键字拦截、超时和行数上限 | 合法 SELECT 通过；写操作、DDL、多语句被拒绝 | 不做外部数据库接入 |
| Day 7 | 学习 LLMProvider 和 NL2SQL | 接入一个模型；实现“2011 年 2 月销售额是多少？”→指标解析→SQL→结果 | 问题可重复得到正确 SQL 和结果；模型输出不直接执行 | 不做双模型切换 |
| Day 8 | 学习受控 Agent 状态 | 实现最小 AgentState、步骤列表和 Tool Router；接入 Metric、Metadata、SQL | Trace 显示问题、指标、SQL、结果和错误 | 不做复杂 LangGraph 分支 |
| Day 9 | 学习趋势和贡献分析 | 实现客户、产品、区域本期/基期差额查询；保留新增和消失对象 | 各维度差额加总等于总变化；不跨维度相加 | 不做毛利复杂拆解 |
| Day 10 | 学习主问题规划 | 实现固定“销售下降归因”策略：趋势→客户→产品→区域→交叉验证 | Agent 完成主问题的完整 SQL 分析链路 | 不做任意问题规划 |
| Day 11 | 主链冻结日 | 修复数字、口径、空结果、零分母和安全边界；补 Visualization Tool | 主问题命中 Ground Truth；生成趋势图和贡献图 | 不新增功能 |
| Day 12 | 学习最小分析页面 | 用 Vue 或简单 HTML 展示提问、步骤、表格、图表、结论 | 不打开终端也能完成一次主 Demo | 不做完整 BI 导航 |
| Day 13 | 学习会话和结果保存 | 保存指标/期间/过滤；支持“再看华东”；输出 Markdown/JSON | 追问继承上下文；保存文件可重新打开 | 不做 Redis 和 PDF |
| Day 14 | 学习复盘和交付 | 准备 8～10 个问题；整理 README、截图、架构图、限制 | 从数据加载到结论保存连续演示 | 不做第二阶段功能 |

## 每天的固定工作节奏

1. 30～45 分钟阅读当天技术概念。
2. 90～150 分钟实现最小功能。
3. 30～45 分钟运行验收和修复。
4. 15 分钟记录学习笔记、问题和下一步。

每天结束时至少保存一个可运行提交或备份、一个验收命令和一段学习笔记。不要把模拟答案写进 Agent；主结论必须来自数据库查询结果。

## 两周验收标准

- 能生成一份固定种子的销售数据。
- 能查询至少 5 个核心指标。
- 能真实回答“为什么 2011 年 2 月销售额比 1 月下降？”。
- 能按客户、产品、区域计算销售变化贡献。
- 能展示 Agent 步骤、SQL、结果和至少两种图表。
- 能进行一次上下文追问并保存 Markdown/JSON 结果。
- SQL 写操作、危险语句、超时和超行数会被拦截。
- README 能让自己在新环境中重新启动和演示。

## 进度落后时的降级顺序

1. 先去掉前端，保留 FastAPI 或命令行 Demo。
2. 再去掉区域和交叉分析，保留客户、产品归因。
3. 再去掉 LLM 动态规划，保留固定策略 + LLM 参数解析。
4. 最后保留 SQL、Metric、Metadata 三个 Tool，Visualization 改成 Markdown 表格。

必须保住数据生成、指标口径、SQL 执行、归因对账和可解释结论这五个学习目标。

## 后续路线

两周完成后再依次增加：Python 受限分析、完整异常检测、前端 Dashboard、RAG、PDF 报告、分析资产版本、多数据源接入、企业权限、双模型和部署工程化。

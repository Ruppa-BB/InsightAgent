# N7 客户×商品组合贡献与连续下钻

2026-10-03，接在N6经营总览之后。金额贡献解释变化来源，不证明业务因果。

## 已实现

分析页支持修改当期/基期日期、国家/客户/商品筛选、指标和趋势分组。贡献明细中的「只看此对象」使用代码而非展示名称；组合同时带客户和商品代码。每次操作生成新分析，沿用会话ID、记录父分析ID，可以返回父记录或取消筛选。旧记录及反馈不会被覆盖。

组合贡献按JSON数组 `[customer_code, product_code]` 构造唯一分组，不用易冲突的字符串拼接。查询在两个期间的并集聚合，因此新增、消失、持续组合全部进入核对。客户、商品、国家及组合各自与同一个销售额差额对账，不能相互累加。展示负向/正向各前10，并保留其余变化合计与完整分组数量；不是逐行导出所有组合。

组合按需开启：比较销售额时点击「客户×商品组合贡献」。单维上限10000组，组合上限100000组，读取上限+1检查；超过限制拒绝，不用截断结果归因。SQL标识符来自固定白名单、过滤值绑定参数；沿用只读快照与超时保护。组合可能更慢，仍受已有数据库超时约束。

## 工具契约

`POST /api/analyses/{analysis_id}/drill` 接受以下可选字段：

- `filters`：country/customer_code/product_code，整个筛选对象替换。未传继承，空对象取消全部；页面点击行在客户端显式合并当前其他筛选。
- `period`、`previous_period`：继承未修改的期间；修改后重新验证先后和5年范围，基期只适用于compare。
- `metric_code`、`group_by`：固定白名单。切换离开销售额同比时转为月份趋势，清除基期；切换客户数且旧分组是客户时改为月份。保留显式业务筛选，所有基础指标均支持这些筛选。订单数、客户数和平均值不运行金额贡献。
- `contribution_dimensions`：customer/product/country/customer_product列表，不重复。只有销售额compare执行贡献；旧记录缺此字段仍按三个单维执行。

未知父记录404，非法参数422；成功结果有 `parent_analysis_id`，并在新记录保存前写入。历史加载与JSON/Markdown导出保留筛选和父关系。下钻查询使用新的只读快照，数据变更后不保证复现旧记录，当前固定零售样本没有跨请求快照重跑。
